# Contributing

[中文版](CONTRIBUTING_cn.md)

Thank you for your interest in OpenEvent.

## Development Environment

Install the dependencies listed in [README](README.md), then run:

```bash
make test
```

## Contribution Guidelines

- Document public behavior in `openevent-sdk/docs/API.md` and update its Chinese
  translation at the same time.
- When changing the gRPC contract, update `openevent-sdk/proto/openevent.proto`
  or `openevent-sdk/proto/admin.proto` according to service boundaries and shared
  package types.
- Python SDK protobuf files are generated by `make build` and `make test` in
  `openevent-sdk` and are not tracked by Git. These two targets must generate them
  rather than assume they already exist in the working tree.
- After modifying proto or SDK-related files, also verify the SDK submodule
  according to `openevent-sdk/README.md`.
- Prefer small, verifiable changes; add or update tests when behavior changes.
- Update documentation when behavior, configuration, or public contracts change.
- Public documentation covers usage, configuration, and API behavior; keep
  internal design and implementation details out of it.
- Keep build products, RocksDB data, temporary tokens, logs, and private notes
  out of commits.
- Keep Markdown links valid for GitHub browsing.

## Pull Requests

Before submitting a pull request, confirm that the build and tests pass and
documentation is up to date. Include:

- A clear summary of the change.
- The commands used for build and test verification.
- Notes about compatibility impact, if any.
- Documentation updates when public behavior changes.
